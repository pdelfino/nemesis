#+TITLE: Guidelines map: from Anthropic's Claude Code best practices to Nemesis affordances
#+OPTIONS: toc:nil

Source of truth: [[https://code.claude.com/docs/en/best-practices][Best practices for Claude Code]] (official, living page), re-read on 2026-OCTOBER-18.

The pillar this map serves: *best practices are the defaults*. The guide is a list of things a user must remember. Nemesis turns each one into a key, a buffer, a command or a visible meter, so the recommended way is the easy way. The measure for any row is one question: does the user still have to remember this, or does the interface do it by default?

* How to use this map

- Every feature issue names the row it serves, or says it serves none.
- When the official page changes, the new guidance becomes a row here before it becomes code.
- A row is "done" when the affordance exists and a spec proves it, never when the prompt text merely recommends it.

** Status on 2026-OCTOBER-18

Done, with a spec in the Proof column: every row except "Automate and scale", "Gate the stop on the check" and "Add an adversarial review step" (#80 to #86, #67, #104, #61 to #63 landed). Waiting on #70, #87 and #28: worktree per window, =review-diff= in a fresh session and the MCP server over the command table, so "Automate and scale" reads "not yet" in full. The one guideline section only partly covered is "Configure your environment": the =environment= buffer is read-only and only CLAUDE.md can be opened for editing, so hooks, skills, subagents, MCP servers and plugins are shown but not authored. The re-read of the official page on this date added two rows from existing text: gating the stop on the check (goal, Stop hook, second opinion) and the adversarial review step, both "not yet", no code.

#70 and #87 landed: "Add an adversarial review step" is done, and "Automate and scale" has multiple windows, a worktree per window and =review-diff= with a spec each; only the MCP server over the command table (#28) is still "not yet" there. "Gate the stop on the check" is unchanged.

#113 landed: "Gate the stop on the check" is done. The cockpit-side gate (option A of the issue) holds the turn end on the verify check and sends a red one back as an ordinary prompt, which is the guide's "set the check as a goal"; the SDK's Stop hook is not used.

* What is deliberately not mapped

- "Develop your intuition": the guide says its own patterns are starting points. Nemesis makes them defaults, not locks; every affordance can be ignored, rebound or disabled from the config.
- Auto mode and the permission classifier: Nemesis routes permissions through the SDK callback under the policy in SECURITY.org (#55), which is stricter than the guide's default while a web page is open.
