#+TITLE: Nemesis security: threat model and non-negotiables
#+OPTIONS: toc:2

This document is read before any feature work. It is written for a careful, non-expert user who is afraid of the web and wants to be no less safe inside Nemesis than inside Brave, and for the agent (Claude Code) that writes most of the code.

* What Nemesis promises

A narrow, testable promise, not a vague one:

1. A malicious or compromised web page cannot escape Chromium's sandbox into the application, the file system or the shell.
2. Nothing is downloaded, opened or executed without an explicit yes from the user, and what is downloaded is quarantined.
3. Transport is HTTPS-only and certificate errors are fatal.
4. Device and data permissions are denied by default.
5. Text read from a web page can never steer the agent into an action. Page content is data.
6. The code and its dependencies are pinned, audited, and updated on a schedule tied to Chromium security releases.
7. Builds that leave this machine are signed and notarized.

* What Nemesis does not promise (say it plainly)

- *Anonymity.* Nemesis does not hide who you are or where you are. Tor Browser is the tool for that, and Nemesis will never claim to be one. If a page should not know your IP address or your browser fingerprint, Nemesis is the wrong tool.
- *Protection from a targeted attacker with an unpatched Chromium exploit.* No browser protects against that. Nemesis shrinks the window by updating fast.
- *Protection from yourself.* If you type a password into a site you were tricked into opening, HTTPS and the URL display help, and a human still decides. Nemesis stores no passwords and autofills nothing in version 1.
- *High-value accounts.* Banking, tax portals and email stay in Brave or Safari until Nemesis is signed, notarized, and has shipped engine updates on time for three consecutive months.

* Threats in scope and their controls

** T1. A page tries to reach the app, the file system or the shell
Controls: Chromium sandbox on for every renderer (=sandbox: true=), one process per site, =contextIsolation: true=, =nodeIntegration: false= and =nodeIntegrationInWorker: false= everywhere, =webSecurity= never disabled, no =allowRunningInsecureContent=, no =experimentalFeatures=, no =enableBlinkFeatures=, no =webview= tag (page buffers are =WebContentsView= instances created by the main process, in =src/main/page-buffer.ts=, with the hardened preferences and no preload but the page-script door's, under the navigation, transport and permission policies before their first load), a preload script that exposes only typed, allowlisted functions through =contextBridge=, and IPC handlers that validate the sender frame's origin before doing anything. The page-script door of ADR 0009 (#130) is the one way the cockpit reads a page: a second preload, =src/preload/page.ts=, attached to page buffers only, runs in the page's isolated world, exposes nothing to the page, answers main's requests by name from a fixed table, and main drops whole any reply that does not come from the top frame of a page buffer it holds, name a request it sent and parse against the schema in =src/shared/page-door.ts=; nothing on either side evaluates text in a page. Two exceptions, ADR 0009's amendment for #141: =query= carries the agent's CSS selector, at most 512 characters, which the preload passes to =querySelectorAll= and nowhere else, answering no selector on a document where a secret field carries a =value= attribute; and =select=, the door's one write, sets a =<select>='s chosen options by index and dispatches =input= and =change=, refused on a secret field, after the user's yes on =browser_select_option=. Electron fuses set at packaging: =RunAsNode= off, =EnableNodeOptionsEnvironmentVariable= off, =EnableNodeCliInspectArguments= off, =EnableCookieEncryption= on, =OnlyLoadAppFromAsar= on, =EnableEmbeddedAsarIntegrityValidation= on. A release is signed with a Developer ID under the hardened runtime, notarized and stapled (#36, =make app-signed=), with one entitlement, =com.apple.security.cs.allow-jit=, which V8 needs (=build/entitlements.mac.plist=; each further one needs a reason there and here); the Agent SDK's CLI binary keeps Anthropic's own Developer ID signature and entitlements and is never re-signed (=signIgnore= in =electron-builder.yml=); =scripts/release-check.mjs --distribution= checks all of it before a tag, and the signature is what gives the asar integrity fuse its teeth.

** T2. Drive-by downloads, malware, dangerous handlers
Controls: downloads are opt-in per file (the user confirms, with the filename, size and origin shown), land in a dedicated quarantine folder, are never opened automatically, and carry the macOS quarantine attribute (asserted by a test). =src/main/security/downloads.ts= (#51) refuses the item a page offers in =will-download= the moment it arrives, because Chromium writes as the bytes come and a paused item that already has them completes on its own; it asks in the prompt buffer, with the no highlighted, and on a yes requests the URL itself, pins that item to =~/Downloads/nemesis-quarantine/= and, when it completes, reads =com.apple.quarantine= back, writes it when missing and removes a file that cannot be marked. Chromium buffers an offer in a hidden temporary file before =will-download= can refuse it, so the app's downloads path is not the user's (#137): startup points it at this run's staging folder in the profile (=download-staging/<pid>/=, owner-only, removed at quit, a dead run's folder removed at the next start), so an offer never touches =~/Downloads= before a yes, and Chromium deletes the buffer of an item it refused. An approval is good for one request within 30 seconds (#100): an item for that URL that arrives later is refused like any other, with a notice that the approval expired, and the user is asked again; on quit every approval is dropped. =shell.openExternal= has one call site, =src/main/security/external.ts= (#51), which launches =http=, =https=, =mailto= and =tel= URLs only, each after a yes in the prompt buffer. External protocol handlers prompt, never auto-launch: a page's =mailto:= or =tel:= navigation is a question; a custom scheme is refused with a notice in version 1, and widening the list is one reviewed constant. =shell.openPath= has one call site too, =src/main/diffs.ts= (#68): =C-c C-o= in a diff buffer hands the edited file to the system's default application, only when the path is absolute, a regular file on disk and inside the session folder (both sides resolved through =realpath=, so a symlink does not step out; #97), and only after a yes in the prompt buffer; the path is the agent's choice, so one outside the folder is refused with a notice and no question; every outcome is a notice in the transcript. The confirm call sites are exactly five, all reading through =src/main/commands/confirm.ts=: downloads, external links, open-file, the verify key (#98: =C-c C-v= asks before a command from an attached issue runs in a shell) and the rewind question (#99: asked before the working tree or the conversation goes back to a checkpoint). =navigateOnDragDrop= off. =tests/e2e/security/downloads-quarantine.spec.ts= offers the fixture three ways and finds nothing written under the downloads path without a yes, by a listing and by a file watcher started before the first offer, one file in the quarantine folder with the attribute after one, and a =mailto:= link that only asks.

** T3. Phishing and insecure transport
Controls: HTTPS-only with upgrade, no click-through in version 1 (=src/main/security/transport.ts=, #52): a page's plain =http= navigation or redirect off loopback is cancelled and re-issued on =https= once, same host and port; if the upgraded load fails, a notice in the transcript says so and nothing falls back to =http=; a page that sends the upgraded load back to =http= is refused, not upgraded again. Plain =http= stays allowed for loopback only, =127.0.0.1= and =localhost= on any port, because the cockpit's users run local dev servers (picked by Pedro on 2026-OCTOBER-18); the mode line marking it =http= in red belongs to the page buffers of M4. Certificate errors are fatal: the one =certificate-error= handler answers false, Electron's own default, and adds a notice naming the host and the error code; =tests/unit/transport.test.ts= greps =src/= and fails if any handler answers true. One test-only seam: when =NODE_ENV=test= and =NEMESIS_TEST_CA= names a PEM file, every session gets a certificate verify proc that accepts a leaf chaining to that one certificate, for the host it names, and defers to Chromium for everything else; the variable is never read outside a test run, and the security harness writes the run's fixture certificate there so the specs can load a page at all. The URL prompt rejects =javascript:=, =file:= and top-level =data:= input, and the navigation policy (=src/main/security/navigation-policy.ts=, #48) refuses those schemes, and anything off =http(s)=, for any navigation that reaches it; from a page, Chromium refuses =file:= and top-level =data:= before a navigation exists, and a page's own =javascript:= URL is not a navigation at all: it runs as that page's script, in that page's origin, and never reaches the app (=tests/e2e/security/navigation-blocked.spec.ts=). Internal pages are served from a privileged custom scheme, never from =file://=, and carry a strict Content Security Policy: =src/main/security/internal-scheme.ts= registers =nemesis://= as standard and secure, serves the built renderer on =nemesis://app= from inside the app and puts the policy on every response as a header (#50); =tests/e2e/security/internal-csp.spec.ts= injects an inline script, an inline handler and a remote script into the cockpit and finds none of them ran. The cockpit, as internal contents, may navigate to =nemesis:= only, with one development exception (#96): when the app is not packaged and =ELECTRON_RENDERER_URL= is set, it may also navigate to that one dev server origin, so the Vite page reload lands; a packaged run, or a run without the variable, has no such origin. The displayed URL is always the committed URL of the top frame.

** T4. Page content steering the agent (prompt injection)
Controls: any text extracted from a page and handed to Claude is wrapped in a delimited block labeled as untrusted content from a named origin, never concatenated into instructions. The agent never executes instructions found in page text. Tools with side effects (sending, submitting forms, purchasing, downloading, running commands, writing files outside the session folder) require the user's explicit confirmation through the SDK permission callback. A =PreToolUse= hook denies side-effect tools while the current buffer is a page from a domain not on the user's allowlist. Every agent action is written to the transcript with its tool name and arguments. The wrapper is =wrapUntrusted= in =src/main/agent/boundary.ts= (#83), and =summarize-page= sends a page buffer's text through it under the cockpit's own instruction (#55); until the page-script door of ADR 0009 lands, that text is the page's committed URL read again through its own partition, cookies omitted, within the limits of =fetch-url=. The side-effect rule is =src/main/agent/page-policy.ts= (#55, option A: the allowlist is empty in version 1, so every page counts): Bash, WebFetch and WebSearch; Write, Edit, MultiEdit and NotebookEdit outside the session folder, where the folder check resolves the nearest existing ancestor of the path through =realpath= so a symlink that points out of the folder is outside (#132); and every MCP tool except the cockpit's own tools whose ADR 0008 class is =free=, read from the catalog (#132); while any page buffer is open its =PreToolUse= hook answers =ask= for them, so the permission bridge asks every call and the =a= list does not answer, and while a page is the current buffer it answers =deny= with no question; each decision is a notice next to the tool call in the transcript. Inside the cockpit the permission bridge offers =y= and =n= only for every page tool of the cockpit's own server, a =mcp__nemesis__browser_= name (ADR 0008, #139): =a= is refused for one and no session allow list answers it, so a yes on a page is always for one call, and =a= keeps its meaning for every other tool. The page tools that act (#140: click, hover, type, press a key, drag, screenshot) synthesize the user's own kind of input from main at the element's centre, never a page script, so the page-script door stays read-only (ADR 0009) but for =browser_select_option='s choice in a =<select>= (#141), which no synthesized input reaches and which =browser_type='s refusal of a masked field covers the same way; their question, at either door, names the client, the tool, the page's origin and the agent's element words quoted, and =browser_type= into a field the masking list of #94 covers is refused before any question: the human types secrets. A full-page screenshot attaches =webContents.debugger= for the one call, sends =Page.captureScreenshot= and nothing else, and detaches. =tests/e2e/security/agent-boundary.spec.ts= summarizes =injection.html= and finds every canary inside the block, a Bash call and an MCP call that is not free each waiting on a yes with a page open, and one denied unasked with a page current, and the session's =browser_click= waiting on a =y= with its page open and denied unasked with a page current.

** T5. Supply chain
Controls: =package-lock.json= committed; =npm ci --ignore-scripts= with Electron's own installer as the single explicit exception; =npm audit --audit-level=high= and gitleaks in CI; Dependabot weekly with Electron grouped; Electron pinned and bumped within a week of a Chromium security release; no dependency without a one-line justification in the commit that adds it; no dependency that needs a lifecycle script; code signing and notarization before any build leaves this machine.

** T6. Permissions and device access
Controls: =setPermissionRequestHandler= and =setPermissionCheckHandler= deny camera, microphone, geolocation, notifications, clipboard read, MIDI, USB, HID, serial and Bluetooth by default. Allow is per site and per session, never persisted in version 1. =setDevicePermissionHandler= denies all devices. The cockpit's own origin, =nemesis://app=, is allowed exactly one permission, =clipboard-sanitized-write=, so =M-w= copies text out of a buffer; it is denied everything else like any site.

** T7. Privacy baseline
Controls: a persistent default session partition for your own browsing and an ephemeral partition wiped on close; WebRTC IP handling set to the public interface only; DNS over HTTPS stays off inside the app so the system hosts blocklist applies; blocker mode on by default; no telemetry, no crash reports leaving the machine, no analytics of any kind. The partitions, the WebRTC policy and the host resolver live in =src/main/security/partitions.ts= (#54). Blocker mode lives in =src/main/pages/blocker.ts= (#126): one request handler per partition, in the main process, cancels a page buffer's request to a host on either of two lists, the system hosts file (every name it sends to =0.0.0.0=, =::= or loopback, read at startup) and EasyList with EasyPrivacy through the Ghostery engine (network filters only, no page script), downloaded again on the =blockerUpdates= schedule (weekly by default, =off= to never) and never before the first page buffer opens; =toggle-blocker= turns it off per buffer, the mode line says so, and =tests/e2e/security/blocker.spec.ts= proves a listed request never reaches the server. No telemetry is not a promise but a spec: =tests/e2e/security/startup-no-network.spec.ts= logs every request each session makes from launch to idle and finds only the app's own files.

* Non-negotiables, each with a test

Every rule below has a test under =tests/e2e/security/= that fails when the rule is broken. A change that removes or weakens one of these is rejected regardless of what else it does, and is never landed on =main=.

| Rule                                                              | Test asserts                                                         |
|-------------------------------------------------------------------+----------------------------------------------------------------------|
| No page can see =process=, =require= or any Node global           | a loaded page evaluating them gets =undefined=                        |
| Every renderer runs sandboxed with context isolation              | =webPreferences= of every WebContents, read at runtime                |
| No =webview= tag, no =allowpopups=                                | =will-attach-webview= rejects; markup scan of internal pages         |
| New windows are controlled                                        | =window.open= from a page yields a controlled buffer or nothing      |
| Navigation is controlled                                          | from a page, =file:= and top-level =data:= never commit, =javascript:= never reaches the app or leaves the page's origin; the policy refuses all three when a navigation reaches it |
| HTTPS-only                                                        | an =http= navigation off loopback never commits (upgraded to =https= or refused), loopback =http= commits, an invalid certificate is fatal with no dialog; the test-only anchor is what lets a spec load a page |
| Permissions denied by default                                     | each listed permission resolves to denied without a user decision   |
| Downloads opt-in and quarantined                                  | a download lands only in the quarantine folder, with the attribute  |
| Internal pages carry a strict CSP                                 | an injected inline script does not execute                          |
| IPC validates the sender                                          | a message from a page origin to a privileged channel is dropped     |
| The page-script door exposes nothing and accepts only its schema  | a page finds no bridge in its world; a reply from a hostile page that breaks the schema, names an unknown =id= or comes from a subframe is dropped; instruction text from a page reaches the agent only inside the labeled block |
| Page text reaches the agent only as labeled data                  | the wrapped block is present and instruction text is not executed   |
| Side-effect tools need confirmation on untrusted pages            | the hook denies without a user decision                             |
| Fuses set at packaging                                            | =@electron/fuses= read-back on the built binary                      |
| No network traffic the user did not ask for                       | from launch to idle, no session requests anything but the app's own files |

* Rules for the agent that builds Nemesis

- Changes under =src/main/security/=, =src/preload/=, the permission bridge in =src/main/agent/=, =SECURITY.org= and the security tests are read line by line in an interactive session before they land on =main=. Since 2026-OCTOBER-19 the repository takes no pull requests and the interactive session lands reviewed work itself (Pedro's call); Pedro reviews on =main= when he wants to. The non-interactive queue may propose such changes on its branch, never land them.
- A security control is written test-first: the failing test lands in the same commit as the control.
- No new dependency without a one-line justification. No dependency that requires a lifecycle script. Prefer Electron and Node built-ins over packages.
- Never log tokens, cookies, page content or prompts to stdout or to files outside the session folder.
- When an Electron or Chromium security release ships, the version bump is the next thing merged.
